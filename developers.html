API Reference

Three endpoints. MCP-native. Stable contract.

Plebify is API-first. Authentication is a bearer token. Responses are deterministic per (question, audience, seed) — rerun the same call, get the same distribution. Or skip the SDK entirely: connect Plebify as an MCP server from Claude Code, Cursor, or any MCP-aware client and ask in plain language.

POST /v1/survey

Run a question against the Persona Library. Returns headline distribution, crosstabs, and representative quotes.

$ curl https://api.plebify.ai/v1/survey \
    -H "Authorization: Bearer $PLEBIFY_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "question":  "Should AI tutors be required in K-12 schools?",
      "scale":     ["yes", "no"],
      "audience":  "census",
      "crosstabs": ["party", "age", "race", "education"],
      "n_quotes":  3,
      "seed":      42
    }'

GET /v1/personas

Browse / filter the Persona Library by any demographic field. Returns persona cards with id, demographics, bio_short, and weight_census. Useful for inspecting who is in the swarm before running a survey.

GET /v1/calibration

Current Pew calibration state. Per-topic-class confidence bands. Use to set expectations before quoting.

$ curl https://api.plebify.ai/v1/calibration -H "Authorization: Bearer $PLEBIFY_KEY"

Auth, errors, rate limits

ConceptHow it works
AuthAuthorization: Bearer <your-key> header. Keys never expire; rotate via dashboard.
DeterminismPass seed to lock the swarm sample. Same call → same distribution. Omit seed for fresh sampling.
Rate limitsFree 10 req/min, Pro 200 req/min, Scale custom. 429 Too Many Requests with Retry-After header on overage.
LatencyP50 1.5s, P95 3s on Pro tier. ZIP-generated audiences add ~30s on first call (subsequent cached).
Errors4xx for invalid request, 503 if swarm capacity is saturated, never silent — every error has a code + suggested fix.
